This guide explains how to use `base_converter.sh` to capture CPU profiling traces and convert them into Perfetto-compatible JSON files.

---

## Overview

The `base_converter.sh` script is a generic utility designed to profile **any** compiled executable using standard Linux `perf record`. It automates the following steps:

1. Runs the specified binary with its associated arguments.
2. Unlocks kernel/hardware counter permissions temporarily (if run with `sudo` permissions or if configured).
3. Saves raw sampling information to `perf.data`.
4. Runs a Python conversion tool (`perf_to_perfetto.py`) to parse the call-stack samples and generate a JSON timeline format.
5. Saves all execution warnings and verbose output to cpu/perf_stat/logs/base_converter.log to keep the console clean.

---

## Dependencies

To successfully run `base_converter.sh` and perform trace conversion, the following dependencies are required:

1. **Linux `perf`**: The standard Linux performance analyzing tool (specifically `perf record`).
2. **Python 3**: Required to run the post-processing script `perf_to_perfetto.py`.
3. **Kernel PMU Permissions**: Recording call-graphs using DWARF stack unwinding requires access to hardware performance counters. Ensure that `kernel.perf_event_paranoid` is set to `-1` to run without root privileges:

   ```bash
   sudo sysctl -w kernel.perf_event_paranoid=-1
   ```

---

## Usage Syntax

Run the script from the root directory of the `profile-scripts` repository:

```bash
./cpu/perf_stat/base_converter.sh --exe <path_to_executable> [options]
```

### CLI Options

| Option | Required | Description |
| :--- | :---: | :--- |
| `--exe PATH` | **Yes** | Path to the executable binary to profile. |
| `--args "..."` | No | Quoted arguments to pass to the executable. |
| `--out-dir DIR` | No | Custom output directory (default: `cpu/perf_stat/traces/base_converter/`). |
| `--convert-only` | No | Skip execution/profiling. Only convert an existing `perf.data` in the output directory. |
| `-h, --help` | No | Display the script help message and exit. |

## Targeted Example: Profiling `muDock`

To profile `muDock` using `base_converter.sh`, make sure you have compiled the `muDock` binary first (refer to [compilazione.md](file:///home/olly/UNI/progetto_aca/profile-scripts_Nedina_Popovschii/utilitis/compilazione.md)).

### 1. Execution Command

From the root of this repository (`profile-scripts_Nedina_Popovschii`), execute:

```bash
./cpu/perf_stat/base_converter.sh \
  --exe ../muDock/build/application/muDock \
  --args "--protein ../muDock/data/1fkb/1fkb_protein.pdb --ligand ../muDock/data/1fkb/ligands100_12col.adtmol2 --use CPP:CPU:0 --population 100 --generations 100"
```

### 2. Output Files Produced

After a successful run, the following files will be created in your workspace:

**cpu/perf_stat/traces/base_converter/perf.data**: The raw performance data generated by `perf record`.

**cpu/perf_stat/traces/base_converter/trace_perf.json**: The converted timeline trace.

**cpu/perf_stat/logs/base_converter.log**: Background warning logs from perf record (e.g. kptr restrictions).

## How to Visualize the Results

1. Open your web browser and go to [ui.perfetto.dev](https://ui.perfetto.dev/).
2. Drag and drop the converted trace file: `cpu/perf_stat/traces/base_converter/trace_perf.json`
3. Use the `W`, `A`, `S`, `D` keys to navigate the timeline, zoom in on function calls, and analyze CPU thread execution tracks.

### Advanced Analysis with Perfetto SQL

To analyze the converted trace file programmatically, you can execute SQL queries directly inside Perfetto UI (click on **Query (SQL)** in the left sidebar) to extract detailed timing and statistics:

#### 1. Identify Top 5 Longest Slices (Bottlenecks)

Finds the individual execution blocks that took the most wall-clock time.

```sql
SELECT 
    name AS event_name, 
    dur / 1e6 AS duration_ms, 
    ts
FROM slice
WHERE dur IS NOT NULL
ORDER BY dur DESC
LIMIT 5;
```

#### 2. Event Statistics (Frequency and Total Overhead)

Aggregates performance data by event name. Helps you see if a bottleneck is caused by a single slow run or many fast invocations.

```sql
SELECT 
    name AS event_name, 
    COUNT(*) AS call_count, 
    SUM(dur) / 1e6 AS total_dur_ms, 
    AVG(dur) / 1e6 AS avg_dur_ms, 
    MAX(dur) / 1e6 AS max_dur_ms
FROM slice
WHERE dur IS NOT NULL
GROUP BY event_name
ORDER BY total_dur_ms DESC
LIMIT 5;
```

#### 3. CPU Time vs. Wall Time (Detecting Blocked Threads)

Compares actual CPU execution time (`thread_dur`) against real-world elapsed time (`dur`). High wall time with low CPU time indicates thread blocking (mutexes, I/O).

```sql
SELECT 
    name AS event_name,
    dur / 1e6 AS wall_time_ms,
    thread_dur / 1e6 AS cpu_time_ms,
    (dur - IFNULL(thread_dur, 0)) / 1e6 AS blocked_time_ms
FROM slice
WHERE dur IS NOT NULL AND thread_dur IS NOT NULL
ORDER BY blocked_time_ms DESC
LIMIT 5;
```

#### 4. Per-Thread Event Breakdown

Maps your custom profiling events to the specific OS threads executing them to check task distribution.

```sql
SELECT 
    thread.name AS thread_name,
    slice.name AS event_name,
    COUNT(*) AS call_count,
    SUM(slice.dur) / 1e6 AS total_dur_ms
FROM slice
JOIN thread_track ON slice.track_id = thread_track.id
JOIN thread USING (utid)
GROUP BY thread_name, event_name
ORDER BY total_dur_ms DESC
LIMIT 5;
```

#### 5. Instant Events / Zero-Duration Markers Frequency

Identifies the most frequent triggers for zero-duration instant milestones.

```sql
SELECT 
    name AS instant_event_name, 
    COUNT(*) AS occurrence_count
FROM slice
WHERE dur = 0 OR dur IS NULL
GROUP BY instant_event_name
ORDER BY occurrence_count DESC
LIMIT 5;
```
